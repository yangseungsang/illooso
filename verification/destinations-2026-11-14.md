# 목적지 검색 및 순정 내비 전달 검증

대상: `1.8.0-destinations` / versionCode 9, Pleos 2.1.0 AVD `emulator-5554`, user 10, 주차 상태. UI 검증은 Android Studio의 실행 중 기기에서 직접 조작했다.

## 구현 범위

- 상단 목적지 버튼에서 장소명·주소 검색과 `순정 내비 목적지 가져오기`를 제공한다. 검색 결과 영역만 스크롤한다.
- 직접 검색은 기존 OSM 원본에 근거한 평거동 주변 8개 POI의 로컬 검색이다. 전국 검색이나 영업 여부 확인은 지원하지 않는다.
- 선택한 목적지 좌표로 정차지와의 직선 거리를 다시 계산한다. 기존 시간·목적·미확인·금지 조건을 적용한 뒤 거리순으로 정렬한다. 보행 경로 거리가 아니다.
- 내비에서 가져온 좌표는 지원 지역 밖이어도 유지한다. 정차지 데이터가 없는 경우 빈 상태를 보여 주며 다른 목적지를 선택할 수 있다.
- 앱의 최종 목적지와 내비에 보내는 승하차 지점을 구분한다. 주 버튼은 선택한 정차지의 실제 좌표를 NaviHelper에 전달한다. 목적지 선택만으로 기존 내비 안내를 변경하지 않는다.
- 입력창은 흰 배경과 짙은 글자를 유지하고 포커스 시 테두리만 강조한다. 후기 화면의 고정 헤더·주 버튼과 본문 내부 스크롤을 유지한다.

## 실제 화면에서 확인한 동작

1. `수영장` 입력 → 신세계수영장 검색 결과 → 선택 → p4 `평거로 북측 예시 주차 공간`, 직선 169m로 갱신됐다.
2. 순정 내비에 목적지가 없을 때 새 빈 목적지 응답을 받아 상태를 안내했다. 이후 실제 안내가 진행 중인 p4를 명시적으로 가져왔을 때 앱 목적지가 p4로 바뀌고 직선 0m로 표시됐다.
3. 재설치 후 선택했던 목적지가 유지됐다.
4. 최종 입력 스타일 수정 후 `극장` 입력 → 청춘극장 검색 결과 → 선택 → 해당 시점 이용 가능한 p1 `평거로36번길 예시 승하차 지점`, 직선 374m로 갱신됐다. 14시에는 p5가 우선하는 단위 테스트와 달리, UI 확인 당시 방문 시각의 이용 조건을 적용한 결과다.
5. p1 전달 후 순정 내비 목적지명과 안내 화면이 p4에서 p1로 바뀌었다. 앱 지도는 청춘극장과 선택한 정차지를 함께 표시했다.
6. 최종 빌드에서 신세계수영장을 다시 선택하고 p4를 전송했다. 기존 p1 안내를 교체하는 동안 앱은 요청 중 상태를 유지했고, 약 11.2초 후 목표 좌표 일치와 실제 `ROUTE_GUIDING` 응답으로 `active`가 됐다. 앱의 `순정 내비에서 안내 중`·`순정 내비 보기`와 순정 내비의 p4 목적지·길 안내 화면을 함께 확인했다. 앱의 최종 목적지 표시는 신세계수영장으로 유지됐다.

## 최종 경로 교체 증거

최종 APK의 실제 SDK 로그 발췌(에뮬레이터 시계 기준):

```text
00:38:38.296 route=requesting targetMatched=false nativeGuidance=false
00:38:38.830 Native cancellation during pending replacement; retaining new target
00:38:49.431 targetMatched=true nativeGuidance=false route=requesting
00:38:49.505 Native route state after target: mode=ROUTE_GUIDING isRouting=false
00:38:49.505 targetMatched=true nativeGuidance=true route=active
00:38:49.579 Navigation screen request submitted; visibility is not acknowledged by SDK
```

순정 내비의 이벤트 제공 방식 차이를 반영해 완료 콜백 외에도 목표 좌표를 확인한 뒤 새로 수신한 실제 안내 상태를 사용한다. 경로 교체 중 이전 경로 취소 이벤트는 새 요청을 초기화하지 않는다. 응답만 없는 경우에는 25초 뒤 실패로 단정하지 않고 `unconfirmed`로 표시한다. 명시적 SDK 오류는 별도로 처리한다.

- `:app:assembleDebug :app:testDebugUnitTest`: 성공. JUnit 42개(장소 15, 선택 4, 후기 8, 지도 투영 5, 목적지 10), 실패·오류 0개.
- 최종 APK를 AVD에 설치했으며 `artifacts/illooso-pleos-debug.apk`가 빌드 출력과 동일함을 확인했다. SHA-256: `80606db41f3d407ee527ee3cdff25116890e6db50bd1b7cf4888e9f28d68f1af`.
- 목적지 테스트는 검색 별칭·주소·공백·대소문자, 잘못된 좌표, 지원 지역 밖, 목적지 변경에 따른 추천 순서, 직선 거리 제한, 이용 시간과 도착 시각, 샘플 불변성을 검증한다.
- 실제 지도 배경은 OSM이며 도로 색상·정차 후보·차량 예상 시간·후기는 예시 데이터다. 지도 등록 POI의 현재 영업이나 현장 출입구·정차 허용 여부를 검증하지 않았다.
- AVD의 순정 내비에서 회전 안내·목적지명·경로 정보는 표시됐지만 배경 지도 타일은 여전히 빈 부분이 많다. 앱 내부 OSM 지도와 별개의 제한이다. 실제 차량 주행은 시험하지 않았다.
